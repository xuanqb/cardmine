# Markdown 题库按章节导入为草稿卡片

上下文：用户有一份 145 个 `###` 题目的前端面试题 Markdown（含题干与答案、10 张 Obsidian 本地图片），希望导入系统复习。生产数据在远程 Docker 服务器，本地无法直连数据库；系统此前只支持 apkg 导入，且现有卡片全是后端方向。导入目标是把每道题变成一张卡片：题干作正面、正文作背面、统一归入「前端」模块，并要求先以 draft 状态入库。文件本身结构不规整：4 个空标题、9 个空答案、「算法」节的答案集中堆在最后一题下且编号与题干错位、图片引用为相对路径。

决定在导入页新增 Markdown 题库入口（应用内上传、可复用），而不是写一次性脚本。上传接受 `.md` / `.markdown` / `.zip`；zip 中自动定位唯一的 Markdown 文件，按引用把图片复制进媒体库并改写为扁平文件名，同名不同内容只报告冲突、不覆盖。解析把 `##` 映射为根模块下的子模块、`###` 映射为题目，去掉 `一、` / `Q2:` / `1.` 等编号与行内标记；空标题跳过，空答案保留为空背面草稿；「算法」节中重复了本节题干的编号答案块视为错位内容、丢弃。导入按正面幂等：正面已存在且背面非空则跳过，背面为空且本次有答案则补全，正面永不覆盖。新卡片状态为 draft、来源为 manual。

为了在格式问题暴露前留出退路，上传默认开启「仅预览，不入库」：完整解析、统计与样例照常返回，但整个事务回滚、不写卡片、模块和媒体文件。另提供默认关闭的「覆盖已有背面」：命中已存在卡片时，仅对来源为 manual 的卡片用本次背面覆盖，crawl / apkg 卡片不动，正面与模块归属也始终不变。

## Considered Options

- 一次性脚本 / 生成 SQL 交给用户在服务器执行：需要人工搬运文件和执行命令，无法复用，且会绕过应用的媒体处理。
- 继续要求用户先转成 apkg 再导入：状态只能落到 ready，无法保留 draft；图片与章节映射也要额外手工整理。
- 每个 `###` 都建卡片、保留错位答案：会把「两数之和」等答案错误挂到其他算法题上，污染卡片内容。
- 重复导入时覆盖已有卡片：会冲掉人工修订过的背面。

## Consequences

- 导入页有第二个上传面板，可填写根模块名（默认「前端」），返回新增 / 补全 / 覆盖 / 跳过 / 空标题 / 模块 / 图片 / 冲突 / 错误的统计，并附前 8 条题目样例供核对格式。
- 默认先预览不落库；确认后取消勾选再导入。格式修好后可勾选覆盖重导，仅覆盖手动导入卡片的背面。
- 模块按 path 只增不删，章节名保留原文（如「Vue相关」），重导时路径稳定。
- 图片以扁平文件名存入媒体库；同名的旧文件保留，冲突列在报告中。
- 「算法」节 5 题目前只有题干（空背面），修正 Markdown 结构后重导可补全背面。
- 导入不生成 Embedding，后续全库扫描时按既有流程懒构建。
