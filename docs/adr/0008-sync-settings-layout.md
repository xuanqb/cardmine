# 同步设置页采用单栏分区与目标卡片

- 状态：已接受
- 日期：2026-11-25

## 背景

多目标同步上线后，设置页「同步」标签沿用了旧的「运行状态 + Anki 同步」双栏骨架，新增的同步目标与组映射只拼了 DOM，没有对应样式。实际页面表现为：

- 左栏内容很短，右栏很长，左侧留下大片空白。
- 每个目标九个按钮平铺换行，主次不分。
- 组映射表格没有表头、列宽和对齐，与站点其他页面不一致。
- 连接状态、统计、批量操作、目标管理和组映射混在一个面板里，层级难辨。

## 决策

### 1. 顶部概览 + 单栏分区

- 同步页不再保留双栏。顶部是一条运行概览：连接状态、AnkiConnect 地址、待推送、已关联笔记、待处理冲突、最近推送。
- 应用版本、数据库、Schema、最近备份收进可折叠的「运行信息」。
- 下面按「同步目标」「组映射」两个面板纵向排列；内容宽度 1080px，900px 以下单列。
- 批量操作（全部同步/推送/拉取、检测连接、接管匹配）放在概览右上角。

### 2. 同步目标用卡片网格

- 每个目标一张卡片，桌面两列、窄屏单列。
- 卡片只保留四个指标：组、待推送、已关联、冲突；最近同步与移出数量放在脚注，错误单独一行。
- 主操作固定为「同步」「推送」「拉取」；检测、接管匹配、体检、同步样式、编辑、删除收进「更多」菜单，删除用危险色。

### 3. 组映射保留矩阵

- 行是顶层组，列是同步目标，保留「组 × 目标」矩阵，因为目标增加时矩阵仍能一屏比较映射关系。
- 表头提供按目标全选/全不选，已勾选单元格着色，行悬浮高亮，外层横向滚动。
- 仍以「保存映射」显式提交，勾选不即时落库。

### 4. 沿用现有视觉变量

- 使用现有 `--bg/--surface/--border/--brand` 等变量，不引入 UI 框架。
- 冲突页同步整理：整卡对比保留左右两栏，标签、边框与按钮层级对齐同步页。

## 后果

- 同步页从「一张长面板」变成三个层次清楚的面板，目标增加时纵向扩展而不是挤在右栏。
- 目标操作有了稳定的主次：日常只需要「同步」，破坏性操作不再与主操作并排。
- 矩阵在目标增多时仍可横向滚动；如果未来目标数超过一屏，需要重新评估是否改为按目标分组的列表。
- 本次只改前端结构与样式，不动接口和同步语义。
