# 高频卡按组内排名写入 Anki 标签

- 状态：已接受
- 日期：2026-11-25

## 背景

卡片已有「出现次数」（`mention` 计数），列表也支持按出现次数排序。用户希望在 Anki 侧直接筛出高频面试题，而不是每次回 cardmine 排序。

静态地把 TOP50/TOP100 存成字段或标签会随排名变化而过期，因此采用同步时实时计算并写入 Anki 标签。

## 决策

### 排名口径

- 每个同步目标、每个顶层组独立排名，只统计映射到该目标且已关联 note 的 `ready` 卡片。
- 按出现次数降序；次数相同按 `updated_at` 降序，再按卡片 ID 降序。
- 取前 50 名和前 100 名，不设最低出现次数，也不因组小而跳过。

### 标签

- 使用两个带命名空间的标签：`cardmine::高频::TOP50`、`cardmine::高频::TOP100`。
- 前 50 名同时带两个标签，第 51–100 名只带 `TOP100`；`tag:cardmine::高频::TOP100` 可筛出前 100。
- 只增删 `cardmine::高频::` 前缀的标签，不读取也不修改其他标签。

### 刷新时机

- 每个目标的推送、拉取、同步成功后自动刷新。
- 通过 `findNotes` 分别找出当前带两个标签的 note，与期望集合求差，再批量 `addTags` / `removeTags`。
- 卡片掉出榜单、移出组（detached）、变为非 `ready` 或 note 被删除时，下一次刷新会摘掉旧标签。
- 标签写入失败只进入任务错误列表，不阻断卡片同步；标签变化算作一次内容变化，会触发备份与 AnkiWeb 同步。

## 后果

- Anki 侧始终反映当前排名，不需要手动维护标签。
- 每个目标最多为「组数 × 100」张 note 打标签；标签名固定为两个，不会产生组合爆炸。
- 每次同步多两次 `findNotes` 和最多四次批量标签写入；无数据库迁移。
- 标签由系统单向维护，用户在 Anki 侧手动删除后，下次同步会被重新加回。
