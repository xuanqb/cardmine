# 归档卡片移出 Anki，但保留去重锚点

上下文：卡片状态此前有 draft / ready / archived，但归档只是一个状态位——不推送、不进全库扫描，却仍占正面唯一键、仍参与采集去重、仍会被回写，Anki 里的笔记也一直保留旧内容。决定把归档定义为「从 Anki 摘掉、在系统里留作去重锚点」：归档只改状态，关联笔记在删除成功前继续存在；下次推送（含抓取结束的自动推送）统一删除归档卡关联的笔记，成功后清空关联、同步基线和待处理冲突，失败则记录错误并在后续推送重试。归档卡保留正面唯一键，继续参与采集相似匹配、全库扫描候选和手动合并，合并后存活卡保持原状态；回写与接管跳过归档卡。删除条数计入变更，确保推送仍会触发 Anki 备份与 AnkiWeb 同步。

## Considered Options

- 归档时立即同步删除：状态变更会依赖 Anki 可用性，失败时要么阻塞归档，要么留下半完成状态。
- 归档即冻结（不参与去重与合并）：采集侧会不断为已归档的问题新建重复卡。
- 归档释放正面唯一键：新卡无法合并到归档卡，与「参与合并」的目标冲突。
- 归档时保留 Anki 笔记：Anki 会长期保留用户已经放弃的内容。

## Consequences

- 归档卡作为合并存活方时，合并结果不会进入 Anki，除非把它改回 ready 再次推送。
- 归档到下次推送之间存在窗口：Anki 笔记仍在，但回写已跳过，期间的 Anki 侧修改不会被采纳。
- Anki 不可用时删除会持续失败，需要在推送结果中暴露并重试。
- 接管来的笔记同样会被删除。
- 删除成功后关联被清空，改回 ready 再推送会新建笔记，note id 会变化。
