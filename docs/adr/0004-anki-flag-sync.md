# Anki 旗帜只读同步，系统只清不设

上下文：背卡时用 Anki 旗帜标记需要修的卡片，系统需要看到旗帜以便定位，并在修完后把旗帜清掉。推送只调用 `updateNoteFields` 和 `changeDeck`，从不写卡片属性；旗帜是卡片属性而非笔记字段。若系统为了同步清除而盲目写 `flags=0`，会把拉取之后新打的旗、换色的旗一起覆盖。决定把旗帜定义为「Anki 唯一来源的待修标记」：拉取时每次都读取已关联笔记的 `flags`（0–7），保存在 `anki_sync`；系统不提供设置旗帜，只提供清除；清除只在系统拉到过该旗帜后产生 `flag_clear_pending`，记录当时的颜色。推送时重读当前旗帜：仍等于待清除值才写 0，已是 0 视为完成且不写，被改成其他值则跳过、以 Anki 为准刷新并取消待清除。清除后卡片保留在「有旗帜」筛选并显示「待清除同步」，推送成功后才消失。系统没有待清除记录时永不写 `flags`，因此未拉取的旗帜不可能被覆盖。

## Considered Options

- 双向同步（系统也能设旗）：需要写非零 `flags`，无法区分「系统想设」与「用户刚在 Anki 设」，会互相覆盖。
- 无条件推送 `flags=0`：会清掉拉取之后新打的旗、改变颜色的旗。
- 用标签代替旗帜：偏离用户既有背卡习惯，且会改动笔记的 tags。
- 旗帜只在系统内展示、清除永远回 Anki 手动做：修完卡还要回 Anki 找卡片，违背「快速定位」的初衷。

## Consequences

- 拉取多一次 `cardsInfo`；若该接口不返回旗帜，退回 `flag:N` 搜索。
- 旗帜变化不产生冲突，也不改变卡片的 draft / ready / archived 状态。
- 清除后到推送成功之前，卡片继续出现在「有旗帜」筛选；推送失败可重试。
- 推送前发现颜色被改，系统以 Anki 为准刷新，用户需要重新决定是否清除。
- 归档推送会删笔记，旗帜随之消失；未关联的孤儿笔记不参与旗帜同步。
