# 按组隔离采集与去重

上下文：题库同时包含后端八股文与前端八股文，后端由一份现成的八股文资料整理而来，前端另有一份题库和一个独立 RSS 面经源。此前系统只有一套全局去重：正面的规范化文本在全库唯一，合并别名、向量扫描、审核候选与 Anki 接管都跨模块匹配。把前端来源接进来后，同一个问题可能前后端各需要一张卡（例如「介绍一下闭包」与后端概念题并不共享答案），全局唯一会强行合并；反过来，前端模块也可能与后端模块混用候选。用户要求来源可以配置目标组，并且组内完整隔离。

决定引入「组」：组就是顶层模块，来源、卡片和合并别名都带 `group_id`。RSS 来源必须指定目标组（可为空，即未分组）；切题时只给模型该组子树内的模块路径，AI 只能在组内新建子路径；精确匹配、别名匹配、向量候选、全库扫描、审核合并与 Anki 接管都只比较同组对象。未分组（`group_id IS NULL`）只与未分组互相匹配，不与任何组互通。来源的目标组是唯一准绳：一篇文章不会因为内容被改判到别的组，无合适模块时卡片留在该组但不挂模块。

数据库层面，`knowledge_point.front_norm` 与 `kp_alias.front_norm` 从全局唯一改为 `(group_id, front_norm)` 唯一；由于 SQLite 的唯一索引把 NULL 视为互不相等，未分组另建 `front_norm` 的 partial unique index，保证未分组内部仍然唯一。已有卡片按所在模块的顶层祖先回填组，旧 RSS 源回填到现有卡片最多的组；没有模块的旧卡片保持未分组。

## Considered Options

- 用模块本身作为去重范围：模块会随 AI 新建而碎片化，父子/兄弟关系需要额外规则，且无法表达「整个前端题库是一套」。
- 继续全局唯一、靠人工合并：前端与后端的同名问题会被误合并，或需要持续人工拆分。
- 按来源 URL 区分：同一来源可能跨方向，且导入的卡片没有来源 URL。
- 在代码里写死前端 RSS 地址：地址属于用户私有资源，不应进入仓库；来源与目标组都必须能在界面里配置。

## Consequences

- `013_group_scope.sql` 给 `feed`、`knowledge_point`、`kp_alias` 加 `group_id` 并重建相关唯一索引；回填按顶层模块完成。
- 面经页新增「来源管理」：可手动添加 RSS、选择目标组、启停、修改目标组与删除，并显示每个来源的面经数与问题数；可新建一个空的顶层组。
- 切题提示词按来源组收敛模块列表，AI 新建路径不能跨组。
- 导入按目录树顶层归组：Markdown 题库的根模块即组，apkg 的顶层牌组即组，组内按正面幂等。
- Anki 接管按牌组对应的组匹配正面，避免不同组同名卡片互相抢笔记。
- 历史别名和合并记录在回填时按存活卡所在组归组；跨组合并在接口层被拒绝。
