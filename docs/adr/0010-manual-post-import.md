# 粘贴旧面经时走采集链路并保留出现次数

- 状态：已接受
- 日期：2026-11-25

## 背景

RSS 只能拿到最新面经，用户还有一批纯文本旧面经。直接走 Markdown/apkg 导入只会生成卡片，不产生 `mention`，旧面经无法参与出现次数统计和高频排名。

## 决策

- 导入页新增「粘贴旧面经」：只支持粘贴，不支持纯文本文件上传。
- 一次粘贴视为一场面试，生成一篇 `post`；多场面试由用户分次导入，保证同一题在不同场次分别累计。
- 必须先选择顶层组；AI 切题、新建模块和去重都限制在该组内。
- 标题选填；留空时取正文第一个非空行（去掉行首 `#`），仍为空才用「手动导入 + 日期」。
- 粘贴提交后直接创建 `post` 并入队，后台完成「补全向量 → AI 切题 → 归并」，流程与 RSS 采集一致，不再提供预览勾选步骤。
- 页面通过 `GET /api/import/{job_id}` 轮询进度，完成后展示汇总和逐题结果（新建 / 关联到哪张卡 / 待确认）。
- 入库复用现有 `mention` 写入与 `Merger` 去重：同一组内相同或向量相似的正面关联到已有卡片，只增加出现次数；新题创建 draft 卡片。
- 手动任务与 RSS 采集共用互斥锁，避免同时写入；同一时间只允许一个导入任务运行。
- 每个组按需创建一个 `manual://group/{id}` 的停用 feed 作为来源，post 在面经页显示为「手动导入 · 组名」，不参与 RSS 采集。
- 文本上限与 AI 切题输入一致，超过 16000 字要求拆分导入。
- 导错组时调用 `DELETE /api/import/posts/{post_id}` 删除该篇面经及其独占的未作答卡片，再按正确组重新导入。

## 后果

- 旧面经与 RSS 面经使用同一套去重、出现次数、审核和高频标签逻辑。
- 不新增表结构；仅多出停用的手动来源 feed 和对应 post。
- 导入是异步的，AI 失败会在任务状态里报错，post 标记为 failed；手动导入不自动推送 Anki。
- 代价是失去了入库前剔除误切条目的机会，只能在导入后到面经/审核页处理。
